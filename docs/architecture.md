# Architecture

Next.js App Router, TypeScript, React, Tailwind CSS, Knex 3 and better-sqlite3. SQLite runs in WAL mode with a single connection and transactional mutations. Numbered Knex migrations are checked in. `lib/db.ts` is the persistence boundary; API routing never requires an external database service. Contacts store versionable structured records; application validation lives in `lib/schema.ts`.

`owner` has a fixed primary key of 1, so simultaneous first-run requests cannot create two accounts. Passwords use Node scrypt with random per-password salt and constant-time comparison. Sessions use random 256-bit opaque tokens; the database stores only SHA-256 token digests and expiry. Cookies are HttpOnly and SameSite Strict; production HTTPS installations enable Secure explicitly. Every personal API checks the session. All mutation methods require an exact configured Origin. Login/setup are limited to 8 attempts per 15-minute window per installation (persistently stored), and search to 60. This local single-owner limit prevents spoofed IP headers from bypassing it, but an exposed instance can suffer deliberate temporary login lockouts; add proxy limits for remote access.

Provider secrets use AES-256-GCM with random nonce and authentication tag. The 256-bit key lives in an environment variable separate from SQLite. Public settings omit ciphertext and plaintext keys. Exports omit settings, usernames, password hashes and sessions. There is no prompt/record/key application logging or telemetry.

## Retrieval

For around 500 contacts, locally scan normalized terms across structured fields and notes. A small synonym map links painting/artist to art and coding/software to programming. Rank matches using topic hits, structured expertise, location, and prior result IDs. Detect location constraints and follow-up pronouns. Direct structured matches precede interests-only or unconfirmed-location possibilities. No numerical confidence is shown. Keep at most 12 candidate contacts, at most 1,000 characters per evidence field, a 2,000-character current query and previous query, and a bounded owner profile. Conversation storage keeps the latest 200 messages; the model receives only the previous query, not full history or prior model text.

This is deterministic lexical retrieval, not embeddings. It supports structured fields and notes without a vector service, but arbitrary paraphrases, misspellings, complicated negation, and ambiguous pronouns may need a clearer query. "How do I know her?" uses previous result IDs; when several contacts were shown, include a name to disambiguate. This limitation is visible in the returned recorded facts and tentative labels, rather than disguised by invented confidence.

The model sees an instruction-separated untrusted JSON payload. No tools are defined. Its schema allows only retrieved IDs and supplied evidence keys, rejects duplicates, unknown keys, IDs and ungrounded fields, and contains no natural-language claim surface. Any failure yields local results with a warning. Consent is re-read after endpoint resolution immediately before network transmission and again before using the answer. In-flight data already transmitted cannot be recalled when consent is revoked; queued/not-yet-dispatched requests are rejected.

Endpoints require HTTPS, no URL credentials/query/fragment, and public DNS addresses by default. Address resolution is pinned into the HTTP request's lookup callback to prevent DNS rebinding between validation and connection. HTTP redirects are never followed. Responses have a 128 KB cap and 20-second total request deadline and a 5-second DNS lookup deadline. Errors omit provider bodies and secrets. Private network support is an explicit environment opt-in; never enable it for an untrusted remote owner.

## Known operational constraints

Single process and one database file, appropriate to a laptop. SQLite is not a multi-instance hosted database. Up to 1,000 contacts per import, 100 conversations, and a 2 MB request cap; exported large histories may exceed import limits, so prefer contacts/profile exports or shorten history. Date strings use ISO calendar format. UI-rendered stored text is escaped by React. Import replaces contacts/profile/chats but preserves credentials. A private recovery export is written before changes; if writing fails, replacement fails.
